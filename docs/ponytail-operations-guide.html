1. Architectural Overview & Executive Core Philosophy

Ponytail channels the archetype of the seasoned, minimalist senior developer who reviews fifty lines of generated boilerplate, says nothing, and replaces it with one clean line. Its guiding axiom is: "The best code is the code you never wrote." AI code generators routinely over-engineer solutions—inventing premature abstractions, introducing duplicate helpers, and pulling in multi-megabyte dependencies for single-function tasks. Ponytail forces the agent to exhaust built-in and existing options before authoring any new code.

3. Non-Negotiable Boundaries & Integrity Rules

Ponytail is aggressively lazy regarding the solution, but strictly disciplined regarding integrity, verification, and blast-radius tracing:

× What Ponytail NEVER Cuts

Trust-boundary validations, security filters (SQLi, XSS, SSRF), error handling that safeguards against data loss, accessible semantics (ARIA, keyboard navigation), hardware calibration routines, and anything explicitly required by the user.

✓ Mandatory Test Coverage

Any non-trivial logic (branches, loops, data parsers, financial arithmetic, authentication, state writes) must leave behind a concise unit test or assert-based self-verification. Trivial changes require zero overhead.
Intentional Technical Debt Annotation: Whenever a pragmatic shortcut is implemented to avoid heavy architecture, it must be tagged with: shortcut: <ceiling limit>, <upgrade trigger event>. These are tracked by /ponytail-debt to prevent debt from rotting.

4. Operating Intensity Modes & Command Interface

Intensity Behavioral Enforcement Ideal Deployment Scenario

5. Concrete Scenario 1: Frontend Confirmation Modal Dialog

Requirement: Prompt user with a confirmation dialog before deleting an enterprise resource.

Task: Add confirmation modal before destructive deletion Diff Delta: −32 lines & zero external dependencies
Standard Agent (No Skill) 35 LOC + 1 Dep
npm install @radix-ui/react-dialog
Imports * as Dialog; wraps code in Dialog.Root, Dialog.Trigger, Dialog.Portal, Dialog.Overlay, Dialog.Content, Dialog.Title, and custom styling containers. Introduces bundle bloat, runtime hydration overhead, and dependency security vulnerability surface.
Ponytail Solution 8 LOC • Pure Native
<dialog id="del-dlg"><p>Delete item?</p><button id="c">Cancel</button><button id="d">Delete</button></dialog>
Uses native HTML5 dialog.showModal(). The browser natively traps focus, escapes on Esc, renders built-in ::backdrop, and is fully accessible by default without external dependencies.

6. Concrete Scenario 2: Backend API Rate Limiting (FastAPI)

Requirement: Safeguard an endpoint from denial-of-service spam in a Python FastAPI backend service.

Task: Rate limit incoming API requests to 10 requests per minute Diff Delta: 128 LOC → 10 LOC (−92% Reduction)
Standard Agent (No Skill) 128 Lines Boilerplate
Generates 5 speculative architectures: custom Redis clusters, rolling-window limits, multi-tier middleware, sliding-window algorithms, and multi-endpoint exception tables before the user even establishes scale requirements. Creates high cognitive load and untested failure points.
Ponytail Solution 10 LOC + Explicit Debt Tag
Decorates route with existing slowapi.Limiter in 10 lines.
Appends explicit deferral: # shortcut: in-memory limiter; upgrade to Redis backend when multi-worker clustering is deployed. Satisfies immediate threat with zero friction and a clear evolution path.
